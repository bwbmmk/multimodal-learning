# CIFAR-10 网页演示：把模型搬到浏览器

训练跑完、测试集 89.22%，但"准确率"这个数字本身没有体感。
这一步的目的不是再涨点，而是把模型放到一个能亲手戳的界面上——看它到底在什么情况下会错、错得有多自信。

最终产物在 [`projects/cifar10-demo/`](../projects/cifar10-demo/)，双击 `start.bat` 就能用，手机扫二维码也能用。

---

## 1. 为什么是 ONNX + onnxruntime-web

PyTorch 模型不能直接在浏览器里跑。可选路线有三条：

| 路线 | 做法 | 问题 |
| --- | --- | --- |
| 起一个 Python 服务 | Flask/FastAPI 包住模型，前端发图 | 要一直开着后端，手机上还得连同一台机器 |
| TensorFlow.js | 转 TF → tfjs | 多一道转换，卷积层容易对不齐 |
| **ONNX Runtime Web** | `torch.onnx.export` → `.onnx` → WASM 推理 | 转换链最短，PyTorch 官方支持 |

选第三条：`torch.onnx.export` 是 PyTorch 自带的，中间不引入第二个框架，出错时只需要怀疑一处。

导出时两个关键参数：

```python
torch.onnx.export(
    model, dummy_input, "model.onnx",
    input_names=["input"], output_names=["logits"],
    opset_version=17,        # 17 对 Conv/BatchNorm 的支持最稳
    dynamic_axes={"input": {0: "batch"}},
)
```

`opset_version` 不能随手写最新版：onnxruntime-web 的 WASM 后端对高版本 opset 支持滞后，17 是目前兼容性最好的点。
`dynamic_axes` 把 batch 维放开，是为了以后能一次推多张图，虽然这个 Demo 一次只推一张。

导出前必须 `model.eval()`。忘了这一步，BatchNorm 会用当前 batch 的统计量而不是训练时累积的 running_mean/var，导出结果和训练对不上——而且不报错，只是预测变差，很难查。

导出后核对了一遍参数量：5,803,082，和 PyTorch 侧 `sum(p.numel() for p in model.parameters())` 一致，说明结构没在转换中走样。

## 2. 预处理必须和训练时逐位对齐

这是整个环节最容易错、也最容易被忽略的地方。训练时用的是：

```python
transforms.Normalize([0.5, 0.5, 0.5], [0.5, 0.5, 0.5])
```

等价于 `(x/255 - 0.5) / 0.5`，把 `[0,1]` 映到 `[-1,1]`。前端就必须一模一样：

```js
const scaled = (v / 255 - 0.5) / 0.5;
```

顺序也不能颠倒。常见的错法是先减均值再除以 255，或者忘了 `ToTensor()` 那一步隐含的 `/255`，结果输入分布整体偏移，模型输出全是乱的，但页面照样能显示"结果"，看起来像模型不行。

另外一个容易忽略的点是**通道顺序**：PyTorch 是 `NCHW`，浏览器 `canvas.getImageData()` 拿到的是 `RGBA` 交错排列。要手动拆成三个平面：

```js
// RGBA,RGBA,... → RRR..., GGG..., BBB...
data[i]     = (pixels[i*4]     / 255 - 0.5) / 0.5;  // R 平面
data[i + N] = (pixels[i*4 + 1] / 255 - 0.5) / 0.5;  // G 平面
data[i + 2*N] = (pixels[i*4 + 2] / 255 - 0.5) / 0.5; // B 平面
```

N = 32×32 = 1024。

验证办法很直接：同一张图，PyTorch 里跑一遍拿到 logits，浏览器里跑一遍，逐个数字比。一开始对不上，后来发现是浏览器缓存了旧的 `app.js`，强制刷新后就完全一致了（见下面第 5 条）。

## 3. 页面里最值得看的是那张 32×32 小图

原图 400×300 缩到 32×32 之后，猫可能只剩一团灰。**很多"模型怎么猜错了"的疑问，看一眼这张小图就消失了**——信息在预处理阶段就没了，怪不得模型。

所以页面上把原图和真正喂进模型的 32×32 并排放，并且放大显示（`image-rendering: pixelated`，不然会被浏览器平滑成一坨）。

裁剪方式给了两个选项：

- **中心裁剪**（默认）：保留中间的正方形，符合 CIFAR-10 的构图习惯
- **直接拉伸**：整张图压成正方形，会变形，但不会丢边缘

切换时结果实时变化，可以直观看到"裁剪掉的部分到底重不重要"。

## 4. 局域网让手机也能打开

核心只有一行：监听地址从 `127.0.0.1` 换成 `0.0.0.0`，这样同一 Wi-Fi 下的手机才连得进来。

```python
ThreadingHTTPServer(("0.0.0.0", port), handler)
```

配套做了三件事：

1. **启动时探测本机局域网 IP**，用 UDP `connect(("8.8.8.8", 80))` 拿到出口地址——这比遍历网卡准，能自动跳过虚拟网卡和 VPN
2. **现场生成二维码**，塞进 `assets/qr.svg`，页面右上角显示；换 Wi-Fi 后重启一次就更新，不会指向旧 IP
3. **响应式布局**：宽度小于 720px 时切成单列，并且隐藏二维码（手机上已经打开了，二维码没意义）；选完图后自动 `scrollIntoView` 到结果卡片

Windows 首次运行会弹防火墙提示，必须选「允许访问」并勾上「专用网络」，否则手机端一直转圈——这是最常见的"连不上"原因，不是代码问题。

## 5. 踩过的四个坑

### 坑一：`wasmPaths` 的相对路径被拼了两次

```js
ort.env.wasm.wasmPaths = './vendor/';   // 错
```

onnxruntime-web 内部会以**页面 baseURI** 为基准来解析，结果拼成了 `vendor/vendor/ort-wasm-simd-threaded.wasm`，404，然后报一个和路径毫无关系的"无法初始化推理会话"。

正确写法是把 baseURI 显式拼进去：

```js
ort.env.wasm.wasmPaths = new URL('vendor/', document.baseURI).href;
```

教训：第三方库的"相对路径"配置项，默认相对的是谁，必须查清楚。

### 坑二：`start.bat` 是 LF 换行，双击后一闪而过

文件在 Linux/WSL 侧生成，换行是 LF。cmd.exe 解析 CRLF，遇到纯 LF 的批处理会把行尾一起读进命令里，报错退出（exit 255），窗口一闪就关，看不到任何信息。

修法是把换行改成 CRLF，并且**在 `.gitattributes` 里固化**：

```gitattributes
*.bat text eol=crlf
```

否则下次在别的系统上 clone 又会变回去。

### 坑三：端口"自动切换"其实没生效

原本的写法是先 `bind`，失败就 `port + 1` 重试。但 `allow_reuse_address = True`（`SO_REUSEADDR`）在 Windows 上的语义和 Linux 不同——它允许**两个进程绑同一个端口**，于是第二个实例不报错，直接和第一个抢流量，手机打开时页面时灵时不灵。

改成先探测再绑定：用 `socket.connect_ex` 试连目标端口，能连上就说明被占用，直接换下一个，从根上避免双绑定。

### 坑四：怀疑了半天代码，其实是缓存

浏览器里的 logits 和 PyTorch 差了一截。查了半天的通道顺序、归一化顺序、resize 算法，都没问题。最后强制刷新（Ctrl+F5）就完全一致了——浏览器缓存了旧版 `app.js`。

所以本地调试时给静态资源加了 `Cache-Control: no-store`。同样的问题在手机上更隐蔽（下拉刷新不一定清 JS 缓存），加上响应头之后就没了。

**顺序上的教训**：数值对不上时，先排除"我看到的到底是不是新代码"，再去怀疑逻辑。

## 6. 验证结果

- 10 张示例图，10 类全部预测正确
- 上传 400×300 的非正方形图片，两种裁剪模式都正常出结果
- 手机 390×844 视口下无横向溢出，选图后自动滚到结果卡片
- 单次推理 6~10 ms（WASM 单线程，i5 级别 CPU）
- 浏览器端 logits 与 PyTorch 端逐位一致

## 7. 一个诚实的提醒

这个模型只认识 10 类：飞机、汽车、鸟、猫、鹿、狗、青蛙、马、船、卡车。

给它一张人像、风景或美食，它也会很自信地归到某一类。**这不是 bug，是它根本没见过别的类别。** 拿自己的照片玩的时候，看置信度分布比看最终结论有意思得多——一张"狗 51% / 猫 44%"的图，往往正好卡在模型的决策边界上。

下一步如果要做真正的多模态，这个"只在封闭类别集里做选择"的局限就是必须要跨过去的东西。
