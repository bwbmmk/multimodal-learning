## 阶段 2：CIFAR-10 与泛化能力

状态：基础实验已完成，继续做消融对比。

### 必须掌握

- 彩色图像的三通道输入
- 数据增强：`RandomCrop`、`RandomHorizontalFlip`
- 训练集和验证集必须使用不同的 `transform`
- BatchNorm 的训练/评估行为
- Dropout 只影响训练
- AdamW 与权重衰减
- 余弦退火学习率
- 过拟合与欠拟合的判断

### 必须完成的对比实验

| 实验 | 变量 | 观察指标 |
| --- | --- | --- |
| A | 无增强、无正则化 | baseline |
| B | 只加数据增强 | 验证准确率是否提高 |
| C | 加 BatchNorm | 收敛是否更稳定 |
| D | 加 Dropout + AdamW | 训练/验证差距是否缩小 |
| E | 加余弦退火、增加轮数 | 是否进一步收敛 |

每次只改变一个主要因素，并固定其他设置。比较时看最佳验证准确率、测试准确率和验证损失，不只看最后一轮。

### 当前结论

- baseline 最佳验证准确率为 75.28%，出现过拟合
- 加入数据增强、BatchNorm、Dropout、AdamW 后达到 82.54%
- 训练准确率从接近 98% 降到约 83%，但泛化能力明显提高
- 下一阶段应关注更长训练、学习率调度和网络结构，而不是继续堆正则化

### 常见误区

- 把验证集也做了随机增强
- 用测试集反复调参
- 只汇报最后一轮，而不是最佳验证模型
- 看到训练准确率下降就认为模型变差

## 阶段 4：MalImg 恶意软件图像分类

MalImg 把恶意软件二进制文件转成灰度图像，用图像分类模型识别恶意软件家族。它首先是一个**单模态图像分类任务**，不是天然的多模态任务；但非常适合作为从教学数据集走向真实数据的桥梁。

### 数据特点

- 灰度图，尺寸不统一
- 类别数量多，类别分布通常不平衡
- 同家族样本可能高度相似
- 图像来自二进制字节可视化，纹理和结构比自然图像更特殊

### 正确做法

1. 先做数据审计：类别数量、图片尺寸范围、损坏文件、重复文件。
2. 已知家族闭集分类按类别分层，使各集合覆盖目标家族；另查重复、近重复及有证据的同源分组并隔离。类别分层本身不能防泄漏。整家族留出属于未知家族评估。
3. 统一缩放，例如 `Resize((224, 224))`。
4. 灰度图转三通道，以适配 ImageNet 预训练 ResNet。
5. 使用预训练归一化参数，而不是随意写 `[0.5, 0.5, 0.5]`。
6. 处理类别不平衡：WeightedRandomSampler、类别权重或 Focal Loss。
7. 评价指标不要只看 Accuracy，还要看 Macro-F1、每类召回率和混淆矩阵。

### 推荐实验顺序

```text
简单 CNN baseline
→ ResNet18 从头训练
→ ResNet18 预训练 + 冻结主干
→ 解冻微调
→ 类别不平衡处理
→ Grad-CAM 观察模型关注区域
```

### 常见误区

- 重复、近重复或已知同源样本跨集合，造成评估偏乐观；同一类别跨集合本身不是泄漏
- 只报告总体准确率，忽略少数类
- 直接把灰度图塞进三通道预训练模型而不做通道适配
- 在测试集上反复调阈值

## 阶段 5：真正的多模态学习

### 先理解什么是多模态

多模态不是「用了图片」或「用了深度学习」，而是模型同时利用两种或以上不同模态的信息，例如：

- 图像 + 文本描述
- 图像 + 恶意软件元数据
- 图像 + API 调用序列
- 图像 + 二进制统计特征
- 图像 + 音频

如果 MalImg 只有图片和类别标签，它仍然是单模态图像分类。要变成多模态，需要额外引入文本、结构化元数据或行为序列。

### 推荐路线

#### 路线 A：早期融合

分别把图像和元数据转成向量，在输入分类器前拼接：

```text
图像 → CNN/ResNet → 图像向量 ┐
                              ├→ 拼接 → MLP → 类别
元数据 → MLP → 元数据向量     ┘
```

优点：容易实现，适合第一个多模态 baseline。

注意：不同模态的数值尺度要统一，缺失值要处理。

#### 路线 B：晚期融合

两个编码器各自输出类别概率，再加权平均或学习融合权重：

```text
图像编码器 → 图像预测 ┐
                      ├→ 融合 → 最终预测
元数据编码器 → 元数据预测 ┘
```

优点：某个模态缺失时仍可工作。

注意：要报告单模态和融合后的对比结果。

#### 路线 C：对比学习

用图像-文本配对数据训练两个编码器，让匹配样本在向量空间中靠近，不匹配样本远离。代表方法是 CLIP。

需要掌握：

- 图像编码器与文本编码器
- 投影头
- 相似度矩阵
- InfoNCE / 对称交叉熵损失
- 温度系数
- Zero-shot 分类

这条路线的数据要求更高。没有真实图文配对时，不要为了「多模态」而用标签机械生成文本，否则可能引入标签泄漏。

### 推荐的多模态项目

主线优先做 CLIP 文本搜图：使用真实配对图文，固定评测集，报告 Recall@K 并分析错例。同一图片的多条正确描述应视为有效匹配。

安全方向可选：在能够取得原始样本及样本级配对数据时，融合恶意软件图像与元数据。只有 MalImg 图片时，不能从中直接恢复 PE 导入表或 API 行为：

- 文件大小、节区数量、熵、导入表统计
- 字符串特征或 API 调用序列
- 与样本真实配对的文本；不能根据待预测的真实家族标签生成输入，否则泄漏答案

先做单模态图像模型，再做单模态元数据模型，最后比较早期融合与晚期融合。这样能清楚回答「多模态到底带来了多少提升」。

### 评价原则

- 单模态 baseline 必须存在
- 必须做融合消融实验
- 检查某个模态缺失时的性能
- 不要只报告最好结果，要报告均值与方差
- 小数据集上使用交叉验证或多次随机种子
